# ארכיטקטורה — סקירה ומפת דרכים

סקירה מנובמבר 2026. מה נמצא, מה תוקן, ומה מומלץ בהמשך. המפה של הקבצים נמצאת ב־[CODEMAP.md](../CODEMAP.md), והכללים ב־[CLAUDE.md](../CLAUDE.md).

## התמונה הכללית

- **שכבות:** `app/` (מסכים) ← `components/` (UI) ← `lib/` (מודל, חישובים, אחסון) ← `theme/`. הכיוון נשמר: `lib/` לא מייבא מסכים או רכיבים.
- **אין תלויות מעגליות** בזמן ריצה בין המודולים (נבדק על כל `app/`, `components/`, `lib/`, `theme/`).
- **מקור האמת הוא המכשיר:** כל מודול ב־`lib/` קורא וכותב מפתח JSON משלו (`lib/storage.ts`), ו־`lib/sync.ts` משכפל לענן במיזוג תלת־כיווני. מצבים נגזרים (מפגש חסר, מבוטל בחג) מחושבים בכל טעינה ולא נשמרים, וזה נכון: אין מה שיתיישן.
- **המודולים המרכזיים:** `workplaces` (32 מייבאים), `time` (26), `courses` (25), `reports` (22), `storage` (21).

## מה תוקן בסקירה הזו

### 1. מרשם מפתחות אחד — `lib/keys.ts`

**הבעיה:** שמות המפתחות והכללים שלהם (מה מסונכרן, מה נשאר במכשיר, מה מגובה) היו מפוזרים כמחרוזות ב־20 קבצים. `lib/sync.ts` ו־`lib/backup.ts` החזיקו כל אחד רשימה משלו של מפתחות "מקומיים", והרשימות כבר התפצלו: ארבע העדפות תצוגה (התראות שנסגרו, הצעות ארכיון שנדחו, נעיצת התאריכון, תאריכים עבריים) לא נכללו בכללי הגיבוי, ולכן נגבו ושחזור דרס אותן.

**התיקון:** כל מפתח רשום פעם אחת, עם היקף:
- `synced`: נתוני משתמש, מסונכרנים ומגובים.
- `viewerDevice`: העדפת תצוגה, מסונכרנת בין המכשירים של המשתמש אבל נשארת במכשיר כשצופים בחשבון של אחר, ולא מגובה.
- `device`: לכל מכשיר בנפרד (שפה, ערכת צבעים, סימוני הדגמה).

הסנכרון (`isSyncedKey`), הגיבוי (`isBackedUpKey`) והשחזור (`replaceAllUserData`) גוזרים את הכללים מהמרשם. השחזור מחליף עכשיו רק נתוני משתמש ומשאיר את העדפות התצוגה ואת מצב הסנכרון שלהן.

### 2. תאריכים במקום אחד — `lib/dates.ts`

**הבעיה:** אותן המרות ISO (`Date` ↔ `"YYYY-MM-DD"`) היו כתובות מחדש ב־11 קבצים, בשמות שונים (`iso`, `isoOf`, `isoDay`, `toDate`, `parseISO`…). תיקון באחת מהן (למשל אזור זמן) לא היה מגיע לשאר.

**התיקון:** `isoDate`, `dateFromIso`, `parseIsoDate` ב־`lib/dates.ts`, וכל הכפילויות הוחלפו בהן. `isoDate` עדיין מיוצא גם מ־`lib/dashboard.ts`, לתאימות. פונקציות `shortDate` למיניהן לא אוחדו, כי הן מחזירות פורמטים שונים בכוונה.

### 3. בדיקות יחידה ו־CI

**הבעיה:** לא היו בדיקות בכלל, וה־CI רץ רק אחרי מיזוג ל־`main`. טעות בחישוב שכר, חג או פדיון הייתה מגיעה ישר למשתמש.

**התיקון:**
- Vitest (`npm test`) ב־`test/`, עם תחליפים קטנים ל־react-native ול־AsyncStorage (`test/stubs/`), כך שקוד `lib/` רץ ב־Node.
- בדיקות לכללי התחום הקריטיים: תאריכי חגים (כולל הקדמת יום העצמאות ודחיית תשעה באב), ביטול מפגשים והשפעתו על הפוטנציאל, שעה אקדמית, פדיון "השלמה לשעה שלמה", שכר לדיווח, סינון ההדגמה מהגיבוי, ומרשם המפתחות.
- `.github/workflows/check.yml`: טיפוסים, בדיקות ובניית האתר בכל PR. גם הפריסה (אתר ו־APK) רצה רק אחרי `npm run check`.
- `userDataOnly` ב־`lib/backup.ts` הופרדה לפונקציה טהורה כדי שאפשר יהיה לבדוק אותה.

## פיצול המסכים הגדולים (בוצע)

שלושת המסכים הגדולים פוצלו בלי שינוי בהתנהגות: 4,139 שורות בשלושה קבצים הפכו ל־303 שורות בקובצי המסך, ועוד 32 קבצים ממוקדים.

| מסך | לפני | אחרי | התיקייה |
|---|---|---|---|
| `app/report.tsx` (אשף הדיווח) | 1,845 | 113 | `components/report/` |
| `app/workplace-form.tsx` (טופס מקום עבודה) | 1,392 | 65 | `components/workplaceForm/` |
| `app/reports.tsx` (יומן) | 902 | 125 | `components/journal/` |

**הדפוס, זהה בשלוש התיקיות:**
- `use….tsx` — שתי פונקציות. hook (`useReportWizard` / `useWorkplaceForm` / `useJournal`) שמחזיק את כל ה־state, הטעינה, האפקטים והפעולות. ופונקציית נגזרות (`reportWizardView` / `workplaceFormView` / `journalView`) שמחושבת אחרי שהנתונים נטענו, ומקבלת את הנתונים כבר בלי `null`, כך שהטיפוסים מצטמצמים כמו במקור.
- רכיב לכל חלק (שלב באשף, קבוצה בטופס, תאריכון ביומן), שמקבל את הכול כ־`w` ומפרק רק את מה שהוא צריך.
- `styles.ts` — הסגנונות המשותפים, ו־`shared.ts` — טיפוסים ועזרים ברמת המודול.
- קובץ המסך ב־`app/` מחזיק רק את מסכי הטעינה / הנעילה ואת ההרכבה.

**איך נבדק שאין שינוי בהתנהגות:** אותו תרחיש דפדפן הורץ על הגרסה שלפני ועל זו שאחרי, והפלט היה זהה תו בתו. התרחיש: האשף המלא עד שמירה ו"דיווח נוסף", חזרה לשלב השעות והוספת הפסקה, עריכת דיווח, פתיחת קבוצות בטופס, וויזארד מקום חדש עד "הוספה", והיומן בשתי הלשוניות עם גלילה. צילום השכבה המוצמדת אחרי גלילה זהה פיקסל לפיקסל, ואין אי־התאמות hydration.

**לוגיקה טהורה מחוץ ל־hook:** האימות, התצוגה המקדימה (נטו, שעות אקדמיות, דקות עודפות, שכר ונסיעות) ובניית הדיווח שנשמר עברו מ־`useReportWizard` ל־`lib/reportForm.ts` (`validateReportForm`, `reportPreview`, `buildReportDraft`), עם 10 בדיקות ב־`test/reportForm.test.ts`. נבדק שהדיווח שנשמר זהה לגמרי לגרסה הקודמת (שדות, דקות למונה ושיוך לקורס).

**בהמשך:** באותו אופן אפשר להוציא את האימות והבנייה של טופס מקום העבודה (`useWorkplaceForm` → `lib/`).

## טעינת נתוני מסך (בוצע)

`components/useScreenData.ts` מחליף את הדפוס שחזר ב־18 מקומות (`useFocusEffect` + `Promise.all` + דגל `active`):

```ts
useScreenData(load, deps, onData?)  // → { data, reload }
```

- טוען בכל כניסה למסך ובכל שינוי של `deps`, ומתעלם מתוצאה ישנה (טעינה חדשה שהתחילה, או יציאה מהמסך).
- **טוען מחדש כשהנתונים הוחלפו מבחוץ** (טעינה / הסרה של נתוני הדגמה, איפוס). קודם רק 3 מקומות האזינו לזה; עכשיו כל המסכים.
- `reload()` מחליף את מוני `reloadTick` הידניים (`workplace.tsx`, `report-view.tsx`, `index.tsx`).
- שגיאת טעינה נרשמת ביומן במקום להיבלע.

`components/LoadingScreen.tsx` מחליף את מסך הטעינה שהיה משוכפל ב־13 מסכים.

**נשאר בכוונה עם `useEffect`:** טפסים שמחזיקים עריכה (`app/course-form.tsx`, נתוני המקום ב־`useWorkplaceForm`), שנטענים פעם אחת כדי שחזרה למסך לא תדרוס שינויים שלא נשמרו, ורכיבים שאינם מסך (דיאלוג, בדיקת עדכון, נקודות היום).

**נבדק:** אותו תרחיש דפדפן על הגרסה הקודמת ועל זו (אשף, עריכה, טופס, יומן) נתן פלט זהה. הדיווח שנשמר זהה, `reload()` אחרי העברה לארכיון מרענן את הדף, ואין אי־התאמות hydration.
